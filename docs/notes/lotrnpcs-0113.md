- Built 2026-11-10 on the owner's Windows PC, not committed yet. Owner asked to "fix and implement all of these ideas into the next version" (the audit findings plus [[lotrnpcs-review-answers]] picks; design in docs/design-roster-promotion.md). Both design steps (roster, planned 0.0.113, and branching promotion, planned 0.0.114) went into 0.0.113. `tools/build.py --no-zip` passed with the new 0.0.113 offline checks; releases/lotrnpcs_0.0.113-test.zip. Untested in game (docs/test-checklist.md section 113).
- Design questions Q1-Q6 got defaults, not owner answers: Q1 no roster key of its own (`/recruits roster` and the orders-menu Roster button); Q2 guard posts unnamed, rows show distance and direction (owner confirmed 2026-11-10: "No" to post names); Q3 guards wear the warrior set; Q4 generic names "guard" and "shock trooper" in every faction; Q5 players only, never wild; Q6 Warrior stays, so four cards at 15 XP (Warrior, Guard, Shock, Archer). Ask the owner if any should change.
- Ranks (Promotion.Branches, gen RANK_STATS/BASE_RANK/BRANCH_NAMES): guard health x1.25 damage x0.8, one-handed weapon and always a shield; shock health x0.8 damage x1.25, always two-handed. Owner, 2026-11-10: "Guards should just be shielded units, and shock troops should be the two handed units", chose game stand-ins for the gaps (gen GUARD_SHIELD_STANDIN: Uruk-hai and tormented elves game wood-and-metal shield, Angmar and Gundabad crude shield, wicked dwarves the dwarf shields; SHOCK_STANDIN: game ruined bardiche for the 12 factions without a two-hander). Only the branch gets the stand-in; that faction's other ranks are unchanged. Kept the stat multipliers (owner). Same-price sidegrades (tools/balance/branches.py win rates 0.48-0.53). Both earn XP and can become captain at 40 XP. Old faction configs gain guard/shock values from their own warrior row and PromotePrices at the warrior's price.
- Promotion logic is one method, HiringSystem.PromoteRecruit (src/Hiring.cs), used by the talk menu's "Promote..." and the promotion screen. New lang key talk-promote-nocoin.
- src/Roster.cs: packets, channel, roster and promotion screens (portraits reuse the Joining.cs DummyInventory/AddPassiveItemSlot pattern). Server keeps a small saved summary per recruit (updated on load, unload, order change) so unloaded recruits list as "Not loaded: last seen x / z, n ago"; pre-0.0.113 recruits show "Not seen since the update" until they load. "Map" uses the client's AddTemporaryWaypoint (no server work; marker gone on rejoin). Call, Promote (any distance) and Dismiss (asks first; unloaded ones leave when their area loads) are rechecked on the server.
- Audit fixes: src/SavedData.cs KeepUnreadable, used by the recruit, admin-set faction and spawn-zone loaders, so a save that can't be read is copied to `<key>-unreadable-<UTC time>` and logged before the next autosave writes an empty list over the main key (the world starts without that data; an admin recovers it from the copy, no command for it). The orders packet is rejected when any of X/Y/Z/Fx/Fz is not finite. Per-tick scans, reviewed 2026-11-10: the 1-second OnTick looks up each recruit by id and never scans all entities; Led() (so Followers(), FollowUsed()) does scan LoadedEntities for borrowed guards, but only on player actions and the open roster's 2-second refresh, so not changed.
- Owner's models: rohan_axe (Rohan, one-handed with shield, 1.56 blocks; asked whether to shorten) and the Easterling scimitar replacing the game's Forlorn blade (0.93 blocks). Sources in tools/weapons/source/. Balance tools: Windows workers ran 1 fight instead of the requested count, fixed; results in docs/balance/balance-results-2026-11-10.txt.
