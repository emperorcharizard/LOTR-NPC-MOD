## 1. What the project is

- **Mod:** `lotrnpcs` ("LOTR NPCs"), a Vintage Story code mod (one C# DLL plus generated JSON assets). Author in modinfo: Emperorcharizar.
- **Purpose (user, 2026-10-30):** for a Lord of the Rings themed Vintage Story server. NPCs of the Middle-earth races are dotted around the map. Players either fight them or hire and command them. They should be more believable enemies than vanilla drifters and skeletons.
- **Three goals (design doc):** 1) hired NPCs live at and defend the player's base; 2) players command hirelings in battle against other players and their NPCs; 3) wild NPCs dot the map as enemies.
- **It is one content mod, not a framework or "mod maker" tool**, even though the old project was named "npc mod maker".
- **Target game:** the user's test world runs VS **1.22.7** (.NET 10). The server's game version is unconfirmed, so modinfo has no "game" dependency.
- **Must run on two servers, one without LRC** (LOTR Races and Classes). That's why LRC's race models are bundled inside the mod.

## 8. Gotchas learned the hard way

- A `//` comment before the first `{` breaks PML config parsing.
- PML model codes need the domain prefix (`lrc:orc`, `faraces:dwarf`, ours `lotrnpcs:<race>`). Our `lotrnpcs:presetskinmodel` behavior must come BEFORE `PlayerModelLib:ExtraSkinnable`; same for `lotrnpcs:geartextures`.
- **PML 1.24.0 bug:** `PlayerSkinBehavior.UpdateEntityProperties` calls SetZNear for every skinned entity, shrinking the camera near plane per NPC. Fixed by the `NpcCameraGuard` Harmony prefix (only the local player's entity may run it). Keep it.
- PML wearables tesselator is player-only, so NPC gear uses vanilla `seraphinventory` + addGearToShape. Client PML only re-tesselates when the MODEL changes, so we call MarkShapeModified on skinConfig changes.
- Don't touch LRC dwarf beard `CHARmod/hair` texture warnings; removing that key made dwarves invisible (0.0.33, reverted).
- Combat Overhaul worn-armor resists apply to players only. NPC toughness is set in entity JSON. CO fork aliases old dependsOn ids, so the faction armor CO patches DO apply.
- Hot paths: `TreeAttribute.GetString` interns every read; read `(tree[key] as StringAttribute)?.value` instead. Enumerate `LoadedEntities` directly, not `.Values`. Cache rules in `memory/lotrnpcs-performance.md`.
- Weapons are client-only (DummySlot), so server/CO code never sees a held item. Keep it that way.
- TRTA `co.json` '/class' errors and Angmar empty step-parent warnings in logs are harmless and not ours.
- **Animation checks:** vsapi `AnimationManager` keys running animations by the shape animation name (`AnimationMetaData.Animation`, e.g. `bowaim`), not the entity animation code. Any `IsAnimationActive` call must use the shape name (`EntityBehaviorHeldWeapon.TrackedAnimation`). 0.0.59 got this wrong and the drawn bow never showed.
- **Hotkeys outlive a world:** re-registering on a second world join threw and killed `HirelingOrdersSystem` (0.0.57). `Orders.cs` `SetUpHotkey` reuses the existing key. Keep it.
- **Vintage Story has its own `Func`:** write `System.Func<...>` in files that import `Vintagestory.API.Common`.
- **Armor step parents:** a step-parented piece's from/to/rotationOrigin are relative to its body part. Armor modelled in whole-body coordinates floats (gundabad-bone-armor 0.1.0). `tools/fix_stepparent_armor.py` converts it; `tools/preview/armorpreview.py` shows it.
- **Packed (one-texture) models:** a packed PNG only lines up with a JSON exported after packing. If a model JSON still names separate textures, the packed PNG can't be used with it; ask the owner to re-save the JSON (that's what happened with the bow and the Misty Mountains shield).
- **Armor modelled in body-part groups** (gundabad 0.2.0): `tools/convert_partgroup_armor.py`. Check left/right: the owner's file had right-arm pieces filed under the left arm.
- `tools/preview/vsrender.py` view labels: its 'front' looks at the BACK of the body (the face is on -x).
- `presetskinmodel` only sets a race model an NPC doesn't have yet, so changing a type's model leaves already-spawned NPCs on the old one.
- **The faction test harness doesn't load the game's Lang**: `Lang.Get` throws there. Keep logic testable apart from text (as `XpInfoText.Shown` vs `Line`).
- **Hover text**: the game appends its own lines after every behavior's GetInfoText, so a line "under health" needs the `EntityAgent.GetInfoText` postfix (`XpInfoText`).
- **Server animations come from the type's base shape** (0.0.77): the server refuses an animation that isn't in the entity type's `client.shape.base` (server-debug.log: "attempted to play an animation code which its shape does not have"), whatever the PML race model has. Our own animations must be in `lotrnpcs:entity/humanoid/seraph-faceless` (bundle_lrc `BODIES`), which every NPC type uses.
- **Rank is the entity type**: anything per rank (health, AI, gear, helmets list, title) is rebuilt from the type on load. Promotion therefore swaps the NPC (`PromotionSystem.Promote`).
- **The text patch can't carry PNGs** (moved or new textures): rebase when a round adds images.
